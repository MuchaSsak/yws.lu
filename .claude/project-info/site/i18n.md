## URLs and slugs

- Always prefixed: `/{locale}/{slug}/`, trailing slash always (`trailingSlash: "always"` + Vercel `trailingSlash: true`),
  lowercase kebab, ASCII only (no accents in FR slugs). Anchor ids are English in both locales (`#contact`).
- One route map: `routes.ts` (`ROUTES`, `pathTo`, `alternates`, `routeOf`, `pageStaticPaths`). Links, canonical,
  hreflang, the switcher, the sitemap, e2e and `vercel.json` all read it; nothing writes a path by hand.
- Unknown locale segments (`/de/…`) are 404. `/en` → 308 `/en/` by Vercel's trailing-slash rule [assumption: verify one
  hop on the preview]. No locale-free aliases except `/` and the legacy redirects (`structure.md` § Redirects).

## Root `/`

- `vercel.json`, generated by `scripts/vercel-config.ts`: `Accept-Language` matching `(?i)^\s*fr` → **307** `/fr/`,
  anything else (or no header: Googlebot) → **307** `/en/` [repo: web/scripts/vercel-config.ts]. Only the first
  language counts (no q-value parsing). Temporary on purpose: a 301/308 would make one language canonical for
  everyone [research: seo-structured-data § 2]. To add: `Vary: Accept-Language` on `/` [research].
- Never canonical, never in the sitemap. `src/pages/index.astro` is the safety net if the rule stops matching
  (`astro preview`, a host change): `noindex`, meta refresh to `/en/`, links to both homes [repo: web/src/pages/index.astro].
  logement.lu links to the bare root, so it must keep answering (Q18).
- Never a redirect between `/en/…` and `/fr/…`, and no cookie remembers the switch (no cookies): a French reader with
  an English browser who types `yws.lu` lands on `/en/` and switches once [assumption].

## hreflang and x-default

- Every page × locale lists `en`, `fr` and `x-default`: absolute, self-referencing, reciprocal, from one
  `alternates(site, id)`; the same set goes into the sitemap (`seo.md` § Crawl). Canonical is always the page's own
  locale, never cross-locale.
- **x-default:** home → `https://www.yws.lu/` (the 307 language selector, Google's documented case); every other page
  → its English version (Q19: English [assumption 2026-10-09]; the research suggested FR). One constant flips it:
  `DEFAULT_LOCALE`, which also flips the root fallback.
- 404 and the root safety net carry none. The legal pages (noindex) keep their set (harmless, consistent).
- Inline text in the other language carries `lang` (WCAG 3.1.2): the switcher links, and the mixed-language fallbacks below.

## Language switcher

- One link per locale, labelled by its autonym, **"English" / "Français"** (`AUTONYMS`), never a flag (Windows draws
  flag emoji as letters); `href = pathTo(other, route)` so it **keeps the page**; `hreflang` + `lang` on each link; the
  current one underlined with `aria-current="true"`; 0 KB JS.
- Places: desktop header (both), phone header (the other language only, next to Menu), the menu, the footer.
- The 404 page links both homes in both languages (`structure.md` § 404).

## Workflow (code details: `lingui.md`)

1. Write English in code: `` t`…` `` (msgid = the English text; context when one word has two jobs).
2. `bun run i18n:extract` (`lingui extract --clean`) → `src/locales/{en,fr}/messages.po`.
3. Fill `fr`: existing French **verbatim** from `lib/dictionary.tsx` (`DICTIONARY.fr`, same key as `DICTIONARY.en`;
   JSX entries split per sentence by hand); new French native and logged in `placeholders.md` § New copy.
4. No compile step: `@lingui/vite-plugin` compiles `.po` on import; no compiled catalog is committed.
5. Strict: the production build fails on a message missing from `fr` (`failOnMissing: "catalog"`,
   `failOnCompileError`) [repo: web/astro.config.mjs]; `catalogs.test.ts` (no empty msgstr, same placeholders and tags,
   French spacing below) and `lingui check sync` run in `check`.
- Project texts are dictionary strings, so they move into the catalogs too (brief P3): one message per paragraph or
  list item with a context naming the project, so the HTML gets real headings and lists. Legal pages are new
  long-form text: per-locale content files (`src/content/legal/{en,fr}/`) with a test that both exist with the same
  headings [assumption].

## French rules

- **Existing French is human text:** the client's wording stays [user 2026-10-09]. Typos, grammar mistakes and literal
  (calqued) microcopy are fixed so the French reads natural, each fix listed in `placeholders.md` § French fixes for the
  client's review [user 2026-10-09, later the same day]; body copy keeps its sentences. Fixes go in
  `web/scripts/fr-manual.json` (a manual entry replaces a filled msgstr). Typos found so far:

| Key | As written | Fix |
| --- | --- | --- |
| `projectSportDescriptionWeSparkProjects` | « sans pressionni jugement » | « sans pression ni jugement » |
| same | « du mondequi les entoure » | « du monde qui les entoure » |
| `Educator` (both locales) | « un.e éduacteur.trice » | « éducateur »; moot: Jobs retired, not migrated |
| `projectMobileLearningTitleWeSparkProjects` | "Erasmus +" | proposal "Erasmus+" (the programme's spelling); kept until the client agrees |

- **Microcopy fixed (listed in `placeholders.md` § French fixes):** "Learn more" « Apprendre encore plus » → « En savoir
  plus »; nav "TEC Conference" (English in the French dictionary) → « Conférence TEC »; « Louez votre propriété » →
  « Louez votre bien » (the owner page's own wording and the slug); « Santé à eux ! » → « Merci à eux ! »; and the rest
  of that table. « Postulez maintenant » stays: « postuler » is the usual verb for a colocation.
- **Mixed-language texts in the 2025 dictionary**, decided [assumption 2026-10-09] (Q35):

| Text | 2025 | en page | fr page |
| --- | --- | --- | --- |
| Girlssective, Mobile Learning (Projet V), Les jeunes amis du sport: titles + texts | French in **both** dictionaries | an English translation as msgid (new, for approval) | the client's French, verbatim (+ the typo fixes) |
| The Self Chronicle: title + text | English in both | the client's English, verbatim | new French, native (for review) |
| TEC page, every section | hard-coded English, no French [repo: app/TecConference] | the client's English, past tense (Q8) | new French (for review) |
| `heroDescriptionJobs`, FR `tecConferenceMetadata` | French in en / English in fr | retired / replaced by `seo.md` | retired / replaced |

  Why: msgid must be the English source; Google reads a page's language from its visible text, and an English page
  with French blocks is mixed-language. **Until the client approves the drafts, the fallback ships:** the original
  text inside `lang="fr"` (or `lang="en"`) with a visible "(in French)" / « (en anglais) » label.
- **New French:** written natively, never literally; `vous` as the client does; inclusive forms only where unavoidable,
  with the middle dot the client uses (« participant·e·s »); official names in French (« Corps européen de
  solidarité »), except inside the client's verbatim text; every string listed in `placeholders.md` as "to review".

## Formatting

- **French spacing:** a no-break space (U+00A0) before `: ; ! ?` and `»`, after `«`, and between a number and `%`;
  stored in the `fr` catalog (a whitespace-only change to the client's normal spaces, listed once in `placeholders.md`,
  not a wording change); colons inside URLs and times are untouched; `catalogs.test.ts` fails on a plain space there.
  U+00A0 rather than the narrow U+202F: Montserrat's coverage of U+202F is unverified [assumption]. This supersedes
  `lingui.md` § French "a normal space as the client wrote it".
- **Numbers:** `Intl.NumberFormat(locale)` for the Supabase statistics, at build (the only time they are read, Q13). Percent as the client writes it: "90%" (en), « 90 % » (fr).
- **Dates:** `Intl.DateTimeFormat` with `en-GB` / `fr`, `{ day: "numeric", month: "long", year: "numeric",
  timeZone: "Europe/Luxembourg" }` → "9 April 2026" / « 9 avril 2026 ». Times 24 h; existing strings keep the client's
  form ("14:30–15:30", « 17h00 »); new French times follow it (« 14h30 »).
- **Phones and addresses:** displayed "+352 28 66 22" in both locales, `tel:` in E.164; addresses as the client writes
  them (« 136-138, rue Adolphe Fischer, L-1521 Luxembourg ») in both locales.
- **Lengths:** French runs longer; every box is sized for French, checked by the text-fit gate (`visual-qa.md`).

## Adding a locale (e.g. `de`)

1. `locales.ts`: add the id to `LOCALES`, `AUTONYMS` ("Deutsch"), `OG_LOCALES` (`de_DE`).
2. `routes.ts`: a native slug for every route id (research suggests `wohnen-fuer-junge-menschen`, `wohnung-vermieten`,
   `ueber-uns`, `projekte`, `tec-konferenz`, `datenschutz`, `impressum` [research: audiences-keywords, not covered]);
   `routes.test.ts` fails until every id has one.
3. `bun run i18n:extract` → `src/locales/de/messages.po`; translate natively; the build fails until complete.
4. `seo.md` metadata rows; legal pages in `src/content/legal/de/`; OG images regenerate on build.
5. `vercel-config.ts`: a `^\s*de` rule for `/` before the default → `bun run vercel:config`.
6. hreflang, sitemap and the switcher follow automatically; run the text-fit and e2e gates in the new locale.
   Luxembourgish copy and slugs need a native speaker's check.
