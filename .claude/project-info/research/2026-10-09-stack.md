# Stack research: Astro 7 + Lingui 6 migration, and the Next 16 + Lingui fallback

Research for the yws.lu revamp (P1 research notes, P3 stack decision). Everything checked **2026-10-09**.

**Method.** Versions and dates from the npm registry (`npm view <pkg> version time dist-tags peerDependencies engines`).
Advisories from the GitHub Advisory Database (`gh api /advisories?ecosystem=npm&affects=<pkg>`), filtered for
`next@15.3.8` with `semver.satisfies`. Some defaults were read straight from the published tarballs, not from the docs
summaries: `astro@7.3.8` `dist/types/public/config.d.ts` and `components/Picture.astro`, the `@gltf-transform/cli@4.5.1`
source, the `@lingui/cli@6.9.0` dist, `@react-three/drei@10.7.9` `core/Gltf.js`, `@astrojs/vercel@11.0.13` `dist/index.js`.
The swc_core version of each Next tag comes from `vercel/next.js` `Cargo.toml`. Decoder sizes were measured with
`gzip -9` on the published files. GLB facts come from reading the GLB JSON chunk of `public/models/*.glb`. The docs were
fetched with WebFetch. Nothing was installed in the repo; the tarballs sit in a scratch dir outside it. The proven
reference is the owner's portfolio (`new-portfolio/apps/web`: Astro 7.3.5, Lingui 6.9.0, lingui-for-astro 0.7.1,
static on Vercel without an adapter).

**Stable since 6.0.0** (2026-03-10); `experimental.fonts` is gone. ### 1.8 React Three Fiber in Astro islands

| Point | Finding |
|---|---|
| Directive | `client:only="react"` for anything that mounts `<Canvas>`: WebGL needs the DOM, and drei / three-stdlib / face-api.js touch `window` at import, so SSR (`client:visible`) runs that code in Node at build. Give the fallback slot a sized poster (no CLS) |
| Lazy start | `client:only` loads its JS on page load (like `client:load`) and cannot be combined with `client:visible` → to defer the 3D, use a custom directive (`addClientDirective`, e.g. the portfolio's `client:after-load`) or a small vanilla `<script>` that dynamically imports the scene when the poster nears the viewport |
| One canvas | Each island = its own React root and its own R3F store/WebGL context; several 3D sections on one page means several contexts (browsers cap live contexts at around 16). Keep one canvas per page, or drei `<View>` inside one canvas |
| Weight | portfolio measured R3F + React = 302 KB gz vs three 126 KB vs OGL 14 KB (`technologies.md` § Stack, 2026-10-05) |
| CSP | Astro's `security.csp` (stable 6.0) is a `<meta>` CSP with hashes. Meshopt and Draco both compile WebAssembly → `script-src 'wasm-unsafe-eval'`; drei's DRACOLoader runs a Worker from a blob → `worker-src blob:`; the default Draco path is `https://www.gstatic.com/draco/versioned/decoders/1.5.5/` → a third-party origin (also a privacy note: Google gets the visitor's IP) |
| Lingui in islands | either `I18nProvider` per island root with `getI18n(locale)` (the catalog ships to the browser), or translated strings passed as props (portfolio rule: no catalog in the browser) |

### 3.2 Lingui on Next App Router: the SWC plugin matrix

Lingui's RSC guide (lingui.dev/tutorials/react-rsc) uses the SWC plugin:
`experimental.swcPlugins: [linguiMacroSwcPlugin()]` (from `@lingui/swc-plugin/options`). On the server, `initLingui()` →
`setI18n()` in React `cache`, called in every layout and page. On the client, `LinguiClientProvider` → `I18nProvider`.
`generateStaticParams` returns every locale. A Wasm plugin must match the host's swc_core. Since swc_core 47 it is
"compatible to some extent" (issue #179), and plugins.swc.rs is no longer kept up to date (#204).

| Next | swc_core (Cargo.toml at tag) | @lingui/swc-plugin | Evidence |
|---|---|---|---|
| 15.3.8 | 21.0.1 | 5.5.x (built on 15.0.1) → Lingui **5** only | table in the plugin README; not tested |

## Risks for the migration

1. **R3F/React mismatch in the spike**: R3F 9.2.0 + React 19.3.0 resolves cleanly but runs a React 19.0 reconciler.
   Pin R3F 9.8.1 / drei 10.7.9 / three 0.186.1 before measuring the HouseScene island, or the spike measures a broken
   combination.
2. **Weight of R3F islands**: React + R3F is about 300 KB gz before drei and postprocessing (portfolio measurement). With
   `client:only` + a poster + a lazy directive, LCP stays HTML, but TBT on mid Android needs the spike numbers (S2-style
   gate). OGL or vanilla three for the simple scenes stays the cheaper path.
3. **lingui-for-astro is a single-maintainer pre-1.0 package** (0.7.1, 6 stars). Keep `.astro` copy thin so dropping it
   costs a few `i18n._(msg…)` calls (the portfolio rule).
4. **Native binaries**: `@lingui/native-tools` has no WASM fallback; `bun.lock` must contain the linux-x64-gnu binary
   for Vercel; Node ≥ 22.19 on the build host (the spike's `engines` says ≥ 22.12: raise it to `24.x`).
5. **Static-output gaps**: no request-time middleware (no `Accept-Language` redirect at `/`), and Astro `redirects` /
   i18n root redirects become meta-refresh pages without status codes. The `/` → `/fr/` or `/en/` redirect, the Jobs
   308s and the old Next URLs go into `vercel.json`. Trailing slashes are the host's job: `vercel.json`
   `"trailingSlash": true`.
6. **Astro 7 whitespace default** (`compressHTML: 'jsx'`) can glue inline words together; the spike sets
   `compressHTML: true`, so keep it explicit. The Rust compiler rejects unclosed tags that the Next/JSX code got away with.
7. **CSP and 3D**: WebAssembly decoders need `'wasm-unsafe-eval'`, and Draco needs `worker-src blob:` plus gstatic (or a
   self-hosted copy). Re-encode the models to meshopt and drop Draco. `frame-ancestors` and other header-only directives
   go in `vercel.json`.
8. **Models are mostly textures** (91–96 %): geometry compression alone saves little. `--texture-compress webp
   --texture-size 1024` is the big win; `--simplify` changes shapes (keep it off unless checked).
9. **Supabase at build time**: images and statistics are frozen at deploy. A change in Supabase needs a rebuild (deploy
   hook) or a client-side fetch. Remote images must match `image.remotePatterns`, or they are served unoptimized.
10. **Fallback on Next has its own churn**: 15.3.8 has 31 open advisories, and 15.x support ends about 2026-10-21. The
    fallback means Next 16 (proxy rename, async params, Turbopack) plus a Lingui SWC plugin pinned to the exact swc_core:
    16.3.8 + 6.6.0 is the only confirmed pair; 16.4.0 + 6.7.1 is untested. Lingui 6 cannot run on Next 15.
11. **Freshness**: astro 7.3.8 (1 day), @astrojs/vercel 11.0.13 (1 day), next 16.4.0 (3 days), motion 14.0.0 (7 days),
    Playwright 1.64.0 (2 days), knip 6.41.0 (today). Pin exact versions and keep `bun.lock` frozen (`--frozen-lockfile`).
12. **Vercel Node 20 cut-off**: new deployments on 20.x error since 2026-10-01; the current Next project should be checked
    (`vercel project ls --update-required`) even before the migration.
